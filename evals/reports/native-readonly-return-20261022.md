# Fresh native read-only return and format recovery, 2026-10-22

Scope: one fresh Linux Claude reviewer inspected a real project's form-progress
and creative-style adoption plan through the native wiki adapter. The coordinator
already knew the project. A subsequent retry by that same reviewer is guided
format recovery, not a second independent trial or an efficiency comparison.
Project-specific findings and raw transcripts remain in restricted handoff.

## Actual first pass

The adopted 0.2.3 payload captured one feature card, eight planned context files
and sixteen registered satellite references, with no omitted query candidate.
An explicitly selected Mobile candidate was bound separately from Mobile main;
neither checkout was presented as an installed application or deployment pair.
The parent and delegated task were read-only with no editable paths. Linux
Claude 2.1.280 received Read/Grep/Glob/Bash/Skill tools and host plan mode, without
Edit/Write. This is not a filesystem sandbox: Bash remained available, so the
coordinator also inspected the actual return.

Scoped host events identify the exact 0.2.3 package and a successful Skill call.
The reviewer ran the packaged index/selected-record workflow and read source,
including an output persisted by the host after preview clipping. The report
distinguished existing displays, deferred common behavior and unverified native
screens. It also exposed existing persistence and branch-state gaps missed by the
coordinator's first plan. Those remain static findings awaiting separate project
validation and implementation; no user data or browser session was accessed.

The worker reached a terminal success result and its process was gone before the
final capture. Actual differences across the selected Web/Mobile checkouts were
empty. Nevertheless, the original return failed reconciliation: capability
explanations used `note` rather than `reason`. Pages and unregistered records were
human-readable lists, and references mixed paths with line locators and prose.
The original report, failed reconciliation and unchanged source receipt were
retained. The coordinator did not silently normalize it into a passing return.

## Minimal helper change

The 0.2.4 candidate adds optional `review-template` preparation from an actual
final native capture. It supplies exact capability keys, satellite paths and
unregistered files as keyed objects. Every decision starts `unreviewed`, reasons
are empty, and verified references are empty. `finish` rejects an untouched
template. Each reading view points to this optional command; it is not a new
mandatory reading step or a replacement for native wiki/commit gates.

Container-shape and path-format errors now explain how to prepare a review.
Line ranges and symbols belong in the explanation, while verified references
remain reachable repository-relative files. The helper does not decide whether
a reviewer actually read a satellite or whether its source claim is true.

## Observed recovery

Only after the original process ended, the same session resumed with the 0.2.4
candidate. It actually invoked the template command and read the generated file.
All generated capability statuses were still unreviewed. The worker returned a
corrected review, retaining the important capability gap and unread scope.
Both the existing 0.2.3 helper and the new 0.2.4 helper accepted that corrected
shape with an empty actual diff. Thus the return contract remains compatible.

The unchanged original list-shaped report is rejected with an actionable error
by 0.2.4. A separate omitted-capability mutant is also rejected. Package identity,
Skill call/result and terminal success were observed independently in the resumed
host events. A structural pass still carries `runtime_acceptance: not inferred`
and does not erase the preserved capability gap.
