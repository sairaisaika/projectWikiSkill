# Saved Wiki path basis after trusted startup delivery

## Observation

After normal exact-definition trust, a fresh ephemeral read-only process from
the installed desktop backend received a selected saved-task index. Before any
tool, its first agent message correctly reported random task and owner values
that were absent from the human prompt. It then used the installed snapshot-only
feature and impact expansions and inspected the controlled fixture source. The
reader correctly rejected implementation claims: the fixture had an unset title
and no tags/visibility behavior. A final actual after-capture, review and finish
reported no source edits, structural reconciliation and an intentional capability
gap. A selected earlier zero-hook artifact retained its bytes.

This was one synthetic offline fixture, not a product, an independent blind study,
the running desktop chat, Linux lifecycle delivery or business acceptance. The
execution stream did not separately export hook-start/completion events; hook
execution is inferred from the unseeded startup context and normal launch path.
Existing unrelated MCP startup errors were kept distinct from hook delivery.

The reader's first combined source/page read failed for its page arguments.
Native keys such as `feature.md` were interpreted at the checkout root, but the
native capture had validated them under its declared Wiki directory. A search
and subsequent Wiki reads recovered. The failure was retained; it was not
rewritten as a correct first read or an efficiency improvement.

## Change boundary

`workflow.capture` already stores `wiki_root`, and `validate_native` uses it for
feature/satellite existence checks. `task_view` now returns that saved value in
all/index/feature/impact views together with explicit path bases. The original
native keys stay unchanged for `show --path`; only locating the actual file uses
`root / wiki_root`. Declared peer prefixes retain their existing source behavior.
Missing old/incomplete metadata remains unknown instead of inventing `docs/wiki`.

Snapshot-only views preserve foreign path strings without local resolution,
existence/currentness checks, Git or native commands. Capture, dispatch, return,
artifact checks, model/credential authority and trust policy are unchanged. The
optional lifecycle reader consumes the same projection and keeps its budget and
explicit-overflow behavior. No installed cache is patched by this source change.

Three original-code negative checks actually failed on the missing value: saved
views, a nondefault Wiki directory with a root-level decoy, and lifecycle index
delivery. Their original logs and the earlier model read failure are retained.
Final focused/full checks, source CI, normal adoption and any future installed
reader trial must be reported at their actual completion boundary. A metadata
fix alone does not prove the next agent reads or reasons correctly.

The fixed local full suite ran199 tests:197 passed and two Windows symlink cases
were skipped. The12 engineering fixtures, original Wiki/navigation checks and
diff validation passed. Four focused view/lifecycle cases and actual plain,
legacy-hook and explicit portable-hook package closure passed. A separate
read-only source review found no actionable issue in six selected files; its
data-only checks preserved native keys, foreign strings and the existing hook
budget, without executing package, tests or host operations. Normal source/PR/
main CI and any installed update remain separate from these local observations.
