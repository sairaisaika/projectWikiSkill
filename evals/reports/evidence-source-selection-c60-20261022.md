## Why the existing method remains the authority

[Native adoption](../../project-wiki/references/native-wiki-adoption.md) already
requires exact selected checkouts and separates declarations, deployments and
observations. [Maintenance](../../project-wiki/references/maintenance.md) already
requires the actual comparison source, executor and comparison range, and rejects
missing inputs as passing evidence. [Feature completeness](../../project-wiki/references/feature-completeness.md)
already separates clients, versions, missing implementation and missing acceptance.
The fix is to apply those contracts at the actual consumer and parent-summary seam,
not introduce another global reading gate or source registry.

Two regressions in `tests/test_workflow.py` exercise the existing helper rather
than claiming to reproduce the product's Node environment:

1. Real related Git checkouts have equal contract bytes but different heads and a
   candidate-only consumer. Explicit peer identities survive the index; a refreshed
   parent does not silently rewrite an already-created child's selected peer.
   Returning against a different peer checkout is refused, even though the selected
   contract bytes still match. Absence in the old checkout is not global absence.
2. A real native-router subprocess emits its actual Python executable/version as
   project-owned workflow metadata. Index/feature/impact/full views and delegation
   preserve that witness and its scope. The child still says dispatch was not
   performed; the router's execution is not relabelled as worker or product runtime.

These test source identity and transport boundaries. They do not mechanically
validate an agent's capability prose, discover undeclared candidate branches,
inspect every subprocess, install a hook or certify business behavior. A new inbox
and any already-running child need their own scoped amendment/read/use evidence.
