This is a guided use trial, not a blind benchmark, timing comparison or business
acceptance. Raw packets/transcripts remain private.

## Real scoped use, including misses

A fresh Linux Claude subscription invocation called the project-wiki Skill,
index and three exact impact views. Its initial positional show syntax failed;
it recovered with --packet. It truncated its first impact display, then recovered
the full relevant structures with explicit JSON extraction. Records remaining
available did not prove that the first display delivered them.

It used calendar outline positions to inspect a reschedule seam, distinguished a
configuration registry from function size, and did not label a generated type's
zero functions defective. Next investigations were proposed without claiming
callers, runtime or schema freshness had been verified. Six initial tool calls
and two recovery calls were observed; no time/savings percentage was measured.

Its claim to have read the target mechanism section was overstated: the actual
command selected the first keyword hit in the header. Root inspected arguments
and preserved that result. Two-tool guided recovery still called the next H3 an
H2 and stopped before the diagram. Native section records lacked heading levels;
complete mechanism/diagram reading was not established by either attempt.

The feedback about empty type/config outlines led root to existing table, rule
and debt dictionaries. All three reader destinations actually returned404 because
generated root documents were omitted from the reader list. The native follow-up
emits those existing documents and uses the renderer's real heading line/level to
provide exact end ranges, including nested diagrams. It does not make another
member inventory or declare the three files fully documented.
