# Complete actual-return capture: bounded coordinator case

## Problem and intended capability

A real coordinator used an unchanged-readonly empty-file recipe while returning
an implementation across two selected checkouts. The existing final gate correctly
refused the missing impact coverage. Collecting the actual diff and querying all
of it repaired the invocation. The original refusal and corrected manual return
remain retained. This was a coordinator use/capability gap, not a broken gate.

The new `capture-return` command makes this collection use the same
`repository_changes` implementation as `finish` and read-only baseline advice.
It does not intersect changes with planned or allowed files, infer a different
base, add a project-specific scanner, or attest semantic completeness.

## Explicit execution boundary

The coordinator supplies reviewed native argv again; it must equal the original
capture and still needs explicit native-execution opt-in. No command is selected
from Wiki text or silently executed from a mutable packet. The saved query,
runtime declarations, peer scope, optional selected-source comparison and evidence
policy are retained. Native selection environment remains the caller's responsibility.

Missing peers and changed selected artifacts refuse the operation. Scope, HEADs
and actual source hashes are compared around the native capture. Drift refuses
without an automatic retry. These are checkpoint observations, not continuous
monitoring, a sandbox, an import-closure inference or authenticated provenance.
The native program may still write its reviewed task stamp. A worker forbidden
Git/native execution must continue using saved snapshot views instead.

## Measured checks

Before implementation, the workflow test run retained one CLI failure for the
unavailable command and seven missing-function errors; the original manual
empty-scope refusal control passed. This demonstrates an absent capability,
not a claim that existing final reconciliation accepted the wrong scope.
The intermediate complete workflow run was87tests, with one existing local
symlink skip. No prior result was rewritten as a new pass.

The first implementation passed seven focused tests. The expanded eight-test
set also passes: actual root/peer changes, a normal committed change, new and
planned-untracked inputs, preexisting unselected cache handling, deleted inputs,
unplanned changes retained for the old final rejection, clean and dirty read-only
returns, explicit execution/argv/base guards, evidence drift, unavailable peers,
source/scope changes during capture without retry, strict source identity and CLI
output preservation. Existing final and snapshot-only controls remain required
in the complete suite; focused success does not establish that suite or CI.

A subsequent controlled negative replaced a declared native runtime body after
task capture. The first implementation executed that changed body despite
unchanged argv; the retained private marker test failed. The command now refuses
changed or unverified declared runtime bytes before native execution. Ordinary
Wiki edits remain supported. Intentional runtime changes use the existing manual
review/capture or new-phase boundary. This guards the declared closure, not every
unlisted dependency or the interpreter binary, and is not a trust attestation.

A subsequent independent read-only source review found two additional boundaries
with pure stub probes: replacement after the wrapper's runtime check could become
the native capture's new baseline, and a root path sharing a peer alias could
collapse two physical inputs into one label. Three controls passed and both
counterexamples remained retained. The reviewer executed no real Git or native
process; these are bounded source/orchestration observations.

Two added real temporary-checkout regression tests failed against that candidate.
The repaired capture receives the originally reviewed runtime hashes and checks
its own pre-launch snapshot rather than accepting a replacement baseline. The
shared live capture/source-hash/actual-diff path now refuses ambiguous root/peer
namespaces, including a deleted root path in the diff; a distinct explicit alias
keeps the existing format. Both regression tests pass after repair. The collision
was observed in the existing shared path, without claiming its historical
introduction. Snapshot-only views remain zero-live observations. Hash checks still
do not make the check-to-execution interval atomic or sandbox the program.

## Actual paired-project use

An uninstalled candidate helper was copied with verified identical bytes to the
host that owned an existing two-checkout implementation task. The previous
formal source CLI refused the new command with exit2 and created no output.
The candidate CLI then derived20actual files without a caller file list. Its
file set and all source hashes exactly matched the prior manually corrected
return. This was an existing task, not a fixture presented as an implementation.

The existing source comparison matched the explicitly selected candidates.
Selected original evidence remained unchanged. A fresh review template had the
same keys as the prior reviewed return; those reviewer claims were reused only
after current file/hash/impact equality was checked. The unchanged final gate
returned structural reconciliation true with no issues and both capabilities
still marked GAP. Original failed and corrected receipts were separately checked
unchanged, not added to or substituted for the saved evidence policy.

This demonstrates actual coordinator use of automatic scope collection and the
old independent final check. It is not another product implementation, a blind
evaluation, proof that every source was physically read, new semantic review,
product/backend/device acceptance, automatic host delivery or a measured speedup.
No timings/token savings are claimed. Full source tests, package checks, normal
source adoption and host observations remain distinct evidence layers.

## Adoption boundary

The candidate internal version is0.2.16. The currently installed host and a
running scoped worker were not patched, restarted, reinstalled or trusted by
this source change. No credential, quota, release authorization or project
deployment behavior is managed by this command. CLI remains independently usable;
the manual actual-file path and legacy captures remain supported.

Complete source/CI and final adoption results belong in the subsequent source
return; installation or hook execution must be observed separately. Private
repository identities, paths, revisions, sessions and raw material are omitted
from this public report.
