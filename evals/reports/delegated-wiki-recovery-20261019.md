# Delegated wiki recovery, 2026-10-19

Scope: one real project's bounded implementation handoff and an instructed
read-only retry by the same worker. The coordinator already knew the feature.
This is a recovery case, not a blind trial, timing comparison or product acceptance.
Host paths, private source content and operational logs are intentionally omitted.

## Observed break

The implementation checkout used main while a new feature page and its cited
design/prototype lived in another candidate checkout. The original task referred
to existing wiki entries and a design copy, but did not supply the new feature
page as an accessible, revision-bound input. Shared wiki edits were assigned to
the coordinator. The first report named a nonexistent input file and suggested
a nonexistent wiki path and another debt record despite an existing task debt.
This does not establish that the worker never read any wiki.

The coordinator also encountered the native publication contract too late:
editing a legacy entry required its functional classification and producer/consumer
records. Guessed relation vocabulary and non-locating evidence cells failed the
native generator. Those failures were corrected using the actual parser and
existing source seams; the gates were retained.

## Repair and observed result

The handoff was supplemented with the actual feature-page snapshot, candidate
and implementation identities, original actor/resource rules, affected relation
IDs and a coordinator-owned return location. An old feature entry was linked to
the new one, whose behavior scope was made readable by the native task tool.

On instructed retry the worker:

- returned to the correct existing feature page and debt;
- identified candidate sources absent from its implementation checkout;
- mapped its three pure files to the feature's relationships, retaining every
  unwired route/storage/client edge as missing;
- separated its local tests from real database, browser and release acceptance.

Residual error: the report and retrospective still named a reused utility under
the wrong directory; an existence check and the code import exposed the mismatch.
File modification times also did not establish the original read order or a
precise causal delay. A self-report of reading and a plausible retrospective
therefore remained insufficient evidence.

## Skill change and limits

The maintenance guide now uses a compact handoff inside the existing task:
route and readable input, source identities/missing dependencies, edit seams and
caller-owned guards, affected relations and return owner. Native adoption adds
an early check of the parser/schema and one accepted example before writing many
records. No additional manifest, permission registry or compulsory full-wiki
reading was introduced.

The helper/package suite ran 66 cases: 65 passed and one platform symlink case
was skipped. The target's native wiki suite passed 326 checks and its change-touch
gate passed after repairs. Those establish mechanical consistency. They do not
prove independent adoption, reduced effort, semantic completeness or deployment.
