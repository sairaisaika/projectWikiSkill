# Narrow saved-packet text lookup — 2026-11-16

## Problem and change

Two guided real tasks in the pilot project used saved task readers but paid for a repeated task envelope on each file lookup. File-specific data arrived behind that envelope. Complete pagination existed; this was output cost, not proof of a broken continuation.

Packet feature/impact text now projects the complete selected native record and expansion first, together with task identity, access, currentness, path bases, base and captured peer heads. Repeated envelope keys are named with exact existing readers: a bounded index command and the complete JSON export. Read-only access remains explicit; selected_file_writable is false for a read-only review. JSON exports, lifecycle delivery and the native completion contract are unchanged.

An ordering-only first delivery did not reduce bytes and was returned. The next delivery was returned because peer heads, edit-scope naming and runnable reader commands were incomplete. The final delivery keeps those facts and uses the existing shell quoting helper, including spaces and apostrophes. Old text cursors fail explicitly when their content changes.
