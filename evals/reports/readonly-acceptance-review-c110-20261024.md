# Read-only acceptance review with preserved evidence, C110

This records one real, bounded use of the installed0.2.9 workflow in a coupled
Web/native project. A fresh reviewer inspected a proposed acceptance script;
the familiar coordinator inspected its return and subsequent script repairs.
It is not an independent blind efficiency comparison, a product incident report,
an executed acceptance result or automatic host lifecycle verification.

Private repository identities, source revisions, machine paths, account values,
credentials, clinical content and raw operational artifacts are excluded. The
underlying review, source inventories, projections and observations remain private;
this summary is not a publicly reproducible benchmark.

## Inputs and permission separation

The task concerned profile reference links and whether adding a display link
preserved the product's internal booking path. The coordinator selected explicit
Web and native checkouts, declared runtime inputs and required capabilities, and
used the existing native Wiki router rather than inventing a second feature map.

The proposed script contained credential configuration. Before delegation, the
coordinator created a separate static review copy with whole credential-bearing
lines replaced by omission comments. Line positions were retained. Original-file
and review-copy hashes were recorded separately. The copy was explicitly
non-executable and not byte-identical to the original. Redaction was a caller
preparation step, **not a feature or security guarantee of the plugin**. The
reviewer did not read the original configuration or infer the hidden identities.

That exact redacted copy was selected through the existing
[`--preserve-artifact` policy](../../project-wiki/references/collaboration-workflow.md#selected-evidence-files).
Checkpoint hashing did not prevent writes or establish original provenance.
Because the executable original remained mutable, its current hash had to be
checked separately before applying findings to a later script.

The installed helper bytes were copied for a private Linux invocation and checked
against the selected installed source. This did not upgrade an already-running
worker's scoped plugin or change hooks, trust, manifests or runtime controllers.
The coordinator used actual `capture`, `start --read-only` and `delegate
--read-only`. The child had `allowed_files: []` and could write only its new private
review and consumption inventory, outside the selected repositories.

The coordinator checked live inputs before dispatch. The worker used only
[`show --snapshot-only`](../../project-wiki/references/collaboration-workflow.md#reading-when-the-worker-cannot-invoke-git)
for saved views, respecting its prohibition on Git and native execution. It also
had no authority to run the script, use product HTTP/DB/browser actions, alter
source or deploy. Saved views were labelled as not checking current inputs.

## Observed consumption and return

The reviewer reported reading both selected feature records, all seven exact
planned-file impact records and relevant implementation sections. Its source
inventory distinguished full-file reading, selected sections and whole-file
hashing. All21 omitted candidates remained in the packet and inventory; they
were not silently reclassified as inspected or irrelevant. Clipped displays were
followed by smaller targeted reads before their contents supported findings.

The coordinator read the full review and static script, independently checked
24 Linux and three Windows consumed-file hashes, and inspected the relevant
implementation seams. Matching file hashes establish the selected bytes at
those observations; they do not trace every physical read or certify every
inference. A consumption inventory is reviewer evidence, not telemetry proving
complete reading of every satellite.

After the child stopped, the coordinator used the original workflow to recapture
the actual unchanged repositories, without fabricating an actual `--files` list.
It generated `review-template`, supplied explicit evidence and remaining gaps,
then ran `finish`. The result had empty `actual_files`, no structural issues and
`structural_reconciliation: true`, while retaining an acknowledgement/cleanup
capability gap for the reviewed script. Selected checkout identities and the
preserved review copy matched at the required return checkpoints.

This unchanged return does not observe transient reverted writes, ignored files
or external state. It is structural reconciliation, not permission enforcement,
semantic certification, an executed test or feature completion.

## Findings that changed the next action

The source-backed review identified five defects in the proposed script:

| Proposed evidence | Why it was insufficient | Required correction |
|---|---|---|
| Cleanup located the new row among HTTPS inputs, then used that index among every remove button | A valid pre-existing HTTP row could shift the index, deleting the wrong row before the final comparison detected damage | Locate the unique URL and remove within that same row; reject ambiguous scope |
| Failed readback defaulted to an empty list | Cleanup PUT failure followed by GET failure could compare equal to an empty baseline and report success | Require successful response/envelope/readback; unresolved state remains unresolved |
| Any reference to the expected provider satisfied the visitor check | An older link could pass while the newly saved link was absent | Require the exact unique new URL, visibility and destination attributes |
| Unchanged booking text/hrefs counted as preserved internal booking | Both lists could be empty; the real external button used a click handler rather than an href | Require an eligible enabled control and observe its actual internal-modal behavior before and after writing |
| Partition denial was required to return a literal HTTP404 | The pinned implementation documented a soft-404 rendering boundary | Test rendered denial and absence of protected profile content separately from the recorded status |

These were static, source-grounded failure paths, not executed product failures
or proof that an existing user row had been deleted. The coordinator stopped the
earlier automatic launch and observed its process absent before the intended run.
No claim is made that a file hash or stopped process proves all earlier activity.

The implementation owner repaired the proposed script. The coordinator's later
static follow-up also moved fixture eligibility assertions before writes, replaced
a non-waiting visibility query with an actual visibility wait, and required the
expected default platform label. A real link click was added with an exact
destination-only browser stub: it observes the product anchor opening the intended
URL without requesting a synthetic path from the external provider. It explicitly
does **not** verify that provider's response, availability or endorsement.

The repaired executable script had a new hash, separately checked against the
frozen candidate copy. The coordinator read a new credential-redacted static
copy and closed only the bounded static hold. This was a guided coordinator
follow-up, not a second independent reviewer trial. The original review and its
gap-bearing reconciliation were preserved unchanged; they were not rewritten to
make the later script appear previously accepted.

At this report's cutoff the normal locked candidate chain was building. Actual
save, independent-viewer display, click, booking behavior and cleanup still needed
their runtime receipts. Successful fresh state and response validation are also
different evidence: the helper's status/`ok` checks did not repair every malformed
acknowledgement or unknown-write path in the product. Broader providers, languages,
narrow-screen/native/device behavior and the full product goal remained separate.

## What this establishes for the plugin

Observed: the existing installed workflow delivered constrained native context,
retained selected evidence and omissions, supported a useful independent source
review, and reconciled an unchanged return without hiding a capability gap.
Findings changed the real next action before intended test writes; subsequent
script adoption was checked separately at the frozen source boundary.

Not established: a measured reduction in time or missed links, every future
agent's semantic correctness, independently traced reading, automatic hooks or
trust, complete host handoff, external-provider or business/device acceptance.
No helper, packaged reference, manifest, version, hook or installation changed
for this report. The improvement was application of an existing review contract;
it does not justify a redundant kernel, new Wiki or reinstall.
