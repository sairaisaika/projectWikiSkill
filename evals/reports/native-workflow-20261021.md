# Native workflow recovery trial, 2026-10-21

Scope: a familiar coordinator's guided recovery of an existing Claude task. This
is not a fresh-agent comparison, a latency result or product runtime acceptance.

The Syleli scratch-post editor shared its write endpoint with normal posts but
had a reduced editor and a wrong response-envelope assumption. A first shared
composer candidate exposed a further missing capability: returning to the drawing
canvas discarded the rich draft. The coordinator rejected treating that loss as a
future TODO and used the recovery as the first native workflow pilot.

The real native `wiki-task.ts` was invoked using the installed local Node/tsx
runtime in the independent scratch worktree. Capture/start/delegate succeeded at
Web base `b3214a1bf472ec9975d1710a6dc823a26444b802`, with the selected Mobile checkout
at `f06c5bc3cb0f3f314378dcd354f879d3033e7d79`. The packet retains 16 candidate files,
14 satellite references and one omitted candidate. Seven explicit capabilities
include title/tag editing, drawing round-trip draft preservation, canonical
moderation response consumption and private diary isolation. No project wiki or
source was migrated into the plugin.

The actual resumed worker invoked `workflow.py show` against its delegated packet.
The host persisted the approximately 30 KiB result and returned a 2 KiB preview;
the worker then issued a real Read of that persisted output. This establishes
specific tool use and retrieval, not comprehension or complete semantic compliance.
The retained private transcript contains the matched call/result IDs; no ambient
plugin inventory, private project source or raw conversation is published here.

That transport friction led to explicit index/feature/impact views. The index names
all records and exposes satellite counts, but states that full records have not yet
been delivered. Exact expansion preserves each native record; the complete view
remains available. The real final capture and finish reviewed all 16 actual files
and the selected peer checkout. The worker supplied dispositions for nine distinct
satellite pages; structural reconciliation passed while retaining the explicit
four-language/390/1440 capability gap. Source inspection confirmed the same
PostComposer remains mounted across drawing returns and replaces its managed image
slot. Actual browser draft behavior and small-viewport reachability remain untested.
These are reviewer/source observations, not a tool certification of semantics.

As a counterexample, a private copy of the returned review had one satellite
disposition and the title/tag capability removed. Reconciliation rejected both
specific omissions. The project source was untouched. The root also ran the native
wiki finishing script against its declared Mobile candidate: 344 docs tests passed.
Its pre-commit touch check only saw the earlier claim commit, so it cannot stand in
for the required post-implementation-commit touch gate. The main Mobile checkout
still lacks that older candidate's referenced assignment files; the paired result
is explicitly not a main/main documentation-adoption claim.

No installation, hook trust, deployment or business completion follows from these
results. Worker implementation is still an uncommitted candidate at this checkpoint.

projections, omitted/substituted files, missing satellites/capabilities, unavailable
